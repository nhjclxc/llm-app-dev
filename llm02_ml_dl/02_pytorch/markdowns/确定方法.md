# 如何确定超参数、激活函数、损失函数和优化器

这四类配置不能靠固定公式一次选定。正确顺序是：先由**任务定义**确定输出层和损失函数，再根据网络结构选激活函数与初始化，最后在独立的验证集上搜索学习率、批大小、正则化等超参数。测试集只用于最后一次客观评估，不能用来反复挑配置。

## 1. 先区分：哪些是设计选择，哪些是超参数

| 类别 | 典型内容 | 主要依据 |
| --- | --- | --- |
| 任务定义 | 输入特征、预测目标、类别数、评价指标 | 业务问题和数据标注 |
| 模型设计 | 输出维度、输出层激活、损失函数 | 任务类型与标签形式 |
| 超参数 | 学习率、batch size、层数、隐藏维度、dropout、weight decay、训练轮数 | 验证集实验 |
| 可学习参数 | 线性层的权重和偏置 | 由优化器在训练中更新 |

例如 `y = 2x + 3` 的 `w=2`、`b=3` 是模型要从数据中学习的参数；`lr=...`、`batch_size=...` 和 `epochs=...` 才是人为设定的超参数。

## 2. 总体决策流程

```text
明确任务和评价指标
        ↓
确定输出层形式和损失函数
        ↓
选择最小可用模型与隐藏层激活函数
        ↓
先找合适的学习率，再调优化器、正则化和模型容量
        ↓
使用验证集选出配置，最后只在测试集评估一次
```

一个可靠的实验至少拆分为训练集、验证集、测试集：

- 训练集：更新模型参数。
- 验证集：比较候选超参数和决定早停时机。
- 测试集：在方案已经确定后报告泛化效果。

数据量很小时可采用交叉验证；若数据有时间顺序，验证集和测试集必须在训练集之后，不能随机打乱未来数据到训练集。

## 3. 激活函数如何选择

激活函数主要用于隐藏层提供非线性。若每一层都是线性层，无论叠多少层，整体仍然只是一个线性变换。输出层是否使用激活函数，则由任务和损失函数的约定决定。

### 3.1 隐藏层的默认选择

| 场景 | 首选 | 何时考虑替换 |
| --- | --- | --- |
| 一般 MLP、CNN | `nn.ReLU()` | 出现大量死亡 ReLU 时试 `LeakyReLU` 或 `GELU` |
| Transformer、现代 NLP | `nn.GELU()` 或 `nn.SiLU()` | 通常沿用参考实现 |
| 有负值且希望输出有界 | `nn.Tanh()` | 它容易在绝对值大时梯度变小，不宜作为默认首选 |
| 二分类概率输出 | 通常不在模型中写 `Sigmoid` | 把 logits 直接交给 `BCEWithLogitsLoss` |

推荐从 `ReLU` 开始，因为它计算简单、训练稳定且是很多视觉和 MLP 基线的默认项。`GELU` 常用于 Transformer；`SiLU` 在一些现代视觉/检测网络中表现良好。没有验证集证据时，没必要为了“高级”而替换 ReLU。

### 3.2 输出层和激活函数的搭配

| 任务 | 输出层 | 模型是否显式加激活 | 原因 |
| --- | --- | --- |
| 回归，目标无界 | `nn.Linear(..., 1)` | 不加 | 预测值可以是任意实数 |
| 回归，目标限定在 `[0, 1]` | 线性层 | 可加 `Sigmoid`，或训练后截断 | 需要确保标签和解释方式匹配 |
| 单标签多分类 | `nn.Linear(..., C)` | 不加 `Softmax` | `CrossEntropyLoss` 内部完成稳定的 log-softmax 计算 |
| 二分类或多标签分类 | `nn.Linear(..., 1/C)` | 不加 `Sigmoid` | `BCEWithLogitsLoss` 内部实现更稳定 |

常见错误是：模型先调用 `Softmax`，再传入 `CrossEntropyLoss`；或者先调用 `Sigmoid`，再传入 `BCEWithLogitsLoss`。两种损失函数都期望接收原始 logits，提前激活会改变目标函数并降低数值稳定性。推理时若需要概率，再使用 `torch.softmax(logits, dim=1)` 或 `torch.sigmoid(logits)`。

## 4. 损失函数如何选择

损失函数由目标变量的类型、噪声特点和业务代价决定，而不是单纯由模型类型决定。先检查模型输出、标签 shape 与标签 dtype 是否匹配。

| 任务 | 模型输出 | 标签格式 | 常用损失 | 说明 |
| --- | --- | --- | --- | --- |
| 连续值回归 | `[N, 1]` 浮点预测 | `[N, 1]` 浮点数 | `MSELoss` | 大误差惩罚更重，适合平方误差有意义时 |
| 含离群点的回归 | 同上 | 同上 | `SmoothL1Loss` / `HuberLoss` | 比 MSE 对极端异常值更稳健 |
| 绝对误差更符合业务 | 同上 | 同上 | `L1Loss` | 对大误差不额外放大，但在零点附近优化不如 MSE 平滑 |
| 单标签多分类 | `[N, C]` logits | `[N]`，类别索引，`torch.long` | `CrossEntropyLoss` | 不要先做 softmax |
| 二分类 | `[N]` 或 `[N, 1]` logits | 同 shape 的 0/1 浮点数 | `BCEWithLogitsLoss` | 不要先做 sigmoid |
| 多标签分类 | `[N, C]` logits | `[N, C]` 多热 0/1 浮点数 | `BCEWithLogitsLoss` | 每个类别独立判断 |
| 类别不平衡 | 同分类任务 | 同上 | 带 `weight` 的 CE 或带 `pos_weight` 的 BCE | 权重须来自训练集分布，并观察 F1、PR-AUC 等指标 |

训练损失不一定等于业务评价指标。比如类别极不平衡时，即使使用交叉熵训练，也应以验证集上的 F1、召回率、PR-AUC 或业务成本来选择阈值和模型。

## 5. 优化器如何选择

优化器决定如何依据梯度更新参数；最重要的超参数通常仍是学习率。相同优化器配上不合适的学习率也会发散、停滞或过拟合。

| 场景 | 推荐起点 | 常见初始学习率 | 特点 |
| --- | --- | --- |
| 教学、凸问题、小型线性回归 | `torch.optim.SGD` | 归一化后 `1e-2` 或 `1e-3` | 行为直观，便于理解梯度下降 |
| 常规深度学习基线 | `torch.optim.AdamW` | `1e-3` | 收敛快，默认首选更省心 |
| CNN、较大视觉训练 | SGD + momentum 或 AdamW | SGD 常从 `1e-2` 起；AdamW 常从 `1e-3` 起 | SGD 常有较强最终泛化表现，但更依赖学习率调度 |
| Transformer、预训练模型微调 | AdamW | 常从 `1e-5` 到 `5e-5` 起 | 更适合小学习率微调和解耦权重衰减 |

建议：

```python
# 通用深度学习起点
optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=1e-3,
    weight_decay=1e-4,
)

# 线性回归教学示例
optimizer = torch.optim.SGD(model.parameters(), lr=1e-2)
```

`weight_decay` 是常用的 L2 风格正则化。它不是越大越好：训练误差和验证误差都高时，优先检查欠拟合或学习率；训练误差很低、验证误差明显更高时，再考虑增加 `weight_decay`、Dropout、数据增强或减少模型容量。

## 6. 超参数如何确定

### 6.1 先调学习率

学习率是最优先调的超参数。可在对数尺度上尝试，例如：

```text
1e-5 → 3e-5 → 1e-4 → 3e-4 → 1e-3 → 3e-3 → 1e-2
```

观察前几个 epoch 的训练曲线：

- loss 迅速变成 `inf` 或 `nan`：学习率过大、输入/目标尺度异常，或存在数值问题。
- loss 大幅来回震荡：通常学习率过大。
- loss 平稳下降但非常慢：可尝试提高学习率。
- 训练 loss 持续下降而验证 loss 回升：开始过拟合，应保存验证集最佳 checkpoint 或早停。

不要在线性尺度上只试 `0.001`、`0.002`、`0.003`；学习率的有效范围常跨多个数量级。找到可稳定收敛的范围后，再在邻近值细调。

### 6.2 再调批大小、训练时长和调度器

| 超参数 | 推荐起点 | 调整信号 |
| --- | --- | --- |
| `batch_size` | 32、64 或受显存限制的最大值 | 显存不足则减小；训练不稳定可尝试减小；吞吐量不足可增大 |
| `epochs` | 设置较大上限，配合早停 | 不直接追求固定轮数；取验证指标最佳的轮次 |
| 学习率调度 | 初期可不用；训练后期停滞时加 | 常用 `ReduceLROnPlateau`、CosineAnnealing 或 step decay |
| `weight_decay` | AdamW 从 `1e-4` 起 | 过拟合时增大，欠拟合时减小 |
| `dropout` | MLP 从 `0.1` 到 `0.5` 起 | 过拟合时尝试；不要默认给所有模型堆很大 dropout |
| 隐藏维度/层数 | 从满足任务的较小模型开始 | 欠拟合时增加；过拟合或速度不足时减少 |

批大小和学习率存在耦合：增大 batch 后有时可适当增大学习率，但这不是强制线性规则，必须以验证集稳定性为准。

### 6.3 一次只改少量变量

一次改变所有设置，无法知道结果为什么变好或变坏。推荐实验顺序：

1. 固定数据划分、随机种子、评价指标和一个最小模型。
2. 只搜索学习率，排除 NaN/不收敛的配置。
3. 在较好的学习率附近比较优化器和 `weight_decay`。
4. 观察欠拟合/过拟合，再改模型容量、Dropout 或数据策略。
5. 对少数候选配置重复不同随机种子，确认结果不是偶然波动。

每次记录：代码版本、随机种子、数据版本、超参数、训练/验证指标、最佳 epoch 和耗时。这样调参才可复现。

## 7. 当前 `y = 2x + 3` 示例的具体选择

这个任务是单特征、单输出的连续值回归，正确的最小模型和损失是：

```python
model = nn.Linear(1, 1)       # 输出层不加激活函数
criterion = nn.MSELoss()      # 标签为连续值
```

原始训练输入为 `1..1024`。应只利用训练集的统计量标准化训练和测试输入：

```python
x_mean = x_train.mean()
x_std = x_train.std().clamp_min(1e-6)

x_train = (x_train - x_mean) / x_std
x_test = (x_test - x_mean) / x_std
```

归一化后，可以从下面配置开始：

```python
criterion = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=1e-2)
# 或者：torch.optim.AdamW(model.parameters(), lr=1e-2)
```

该示例不需要隐藏层，因此不需要激活函数、Dropout 或复杂调度器。若保持原始 `x=1..1024` 而不做标准化，`MSELoss` 对权重的梯度量级会非常大，`lr=1e-5` 也可能导致参数反复过冲，最终出现 `inf`/`nan`。

此外，当前测试输入为 `-1..-10`，训练输入为正数 `1..1024`，这是外推测试。线性函数可以合理外推，但在真实的非线性任务中，验证/测试数据通常应与训练数据来自相同分布。

## 8. 训练前检查清单

- 输入、标签和模型参数是否在同一 device，且浮点计算通常使用 `float32`？
- 回归标签是否为浮点数，分类的类别索引是否为 `long`？
- `CrossEntropyLoss` 前是否错误地加了 softmax？
- `BCEWithLogitsLoss` 前是否错误地加了 sigmoid？
- 连续特征是否只用训练集统计量做了标准化？
- 是否划分了验证集，并根据验证指标保存最佳模型？
- 第一个 batch 的预测、loss、梯度和参数是否全为有限数（`torch.isfinite`）？
- 发生 NaN 时，是否先降低学习率并检查输入、标签与梯度范围？

先让一个小模型稳定地在少量样本上过拟合，再扩大数据、模型和训练配置，通常是定位数据管道、损失和优化问题最快的办法。
